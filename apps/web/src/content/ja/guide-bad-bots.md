## robots.txtとは何か

RFC 9309ははっきりと、そのルールは「アクセス認可の一形態ではない」と述べています。クローラーは`/robots.txt`を取得し、自分の名前を指定したグループを読んで、従うかどうかを自ら決めます。その判断をHTTPが強制する仕組みはありません。

## robots.txtを無視するボット

- **スクレイパーやデータ収集業者**：そもそも許可を求めません。多くは一般的なブラウザーのUser-Agentを使います。
- **ユーザーの代わりに取得するフェッチャー**：OpenAI、Perplexity、Google、Metaは、ユーザーの操作で動くフェッチャー（`ChatGPT-User`、`Perplexity-User`、`Google-Agent`、`meta-externalfetcher`）について、人がページを求めたものなのでrobots.txtに従わない場合があると説明しています。Anthropicは、`Claude-User`は従うとしています。
- **方針を公開していないクローラー**：たとえば`Bytespider`には公式ドキュメントがなく、robots.txtを無視していると報告するサイト運営者もいます。
- **なりすまし**：`User-Agent: GPTBot`や`Googlebot`は誰でも送信できます。検索エンジンのUser-Agentを偽装するのは、単純なブロックをすり抜ける古典的な手口です。

## robots.txtから漏れる情報

robots.txtは公開ファイルです。`Disallow: /admin-backup-2024/`という行は、そのパスが存在することを誰にでも教えてしまいます。秘密にしたいものは記載せず、保護してください。

## 代わりに、または併用すべき対策

| 対策 | 止められるもの | 補足 |
|---|---|---|
| robots.txt | robots.txtに従うクローラー | 標準化され、文書化されたシグナル。削除せずに残してください。 |
| User-Agentによる[サーバー設定](page:server-rules) | 名乗っているボット | 名前がわかっているAIクローラーには低コストで効果的 |
| IPアドレス・逆引きDNSによる検証 | 既知のボットを名乗るなりすまし | 運営元が公開している範囲を使用。各[ボットのページ](page:bots)を参照 |
| レート制限 | 名前に関係なく大量にアクセスするスクレイパー | IPアドレスまたはネットワーク単位。サーバーを保護します |
| CDNのボット管理・WAF | 既知の悪質なネットワーク、ブラウザー自動化 | Cloudflare、Fastly、Akamaiなどがボットを分類 |
| 認証 | アカウントを持たないすべての人 | 非公開コンテンツを本当に守れる唯一の手段 |

## 妥当な順序

1. 正直なrobots.txtを公開します。意思を記録する手段であり、EUの行動規範が参照しているのもrobots.txtです。
2. 拒否したいAIボットを、サーバーやCDNで名前を指定してブロックします。
3. 許可するボットは検証し、その名前をかたるなりすましを拒否します。
4. それ以外にはレート制限をかけ、ログを監視します。
